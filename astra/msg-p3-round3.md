## 直してほしいこと 1（最優先・さとるんの指摘）：**押した鍵が金色になって、鍵が消えたように見える**

さとるんの言葉：
> 「シンセひいてるとき、押された鍵盤が消滅してないですか？」
> 「ピアノも黒鍵ひいてるとき、そこが金色になってしまっている気がします」

**Claude が写真で確かめました。さとるんの指摘は正しいです。両方とも起きています。**

- 添付 `p2-rev-black.png`（ピアノ・革命 17.55 拍）：押された**黒鍵が 2 本、薄い金色（ベージュ）の棒**になっています。黒鍵の黒さが完全に消え、白鍵より明るいくらいです。
- 添付 `p2-band-keys.png`（バンド・硝子の環流 60 拍）：シンセの押された**黒鍵が金色の板**になっています。まわりが真っ黒な楽器なので、「黒鍵が消えて、代わりに金色の何かが出た」ように見えます。
- 添付 `p2-clair-left.png`（ピアノ・月の光 100 拍）：押された**白鍵が黄土色**になっています。象牙色の鍵が汚れたように見えます。

原因は両方とも同じ書き方です。

```js
// public/piano/scene.js 409 行 / public/band/scene.js 102・137 行
const mat = (black ? P.ebony : P.ivory).clone();
mat.emissive = new THREE.Color(0xc9a656);   // 金色
mat.emissiveIntensity = 0;
// public/piano/scene.js 766 行 / public/band/scene.js 587 行
k.mat.emissiveIntensity = k.press * (k.black ? 1.1 : 0.55);
```

黒鍵はもともと真っ黒（バンドは `0x050607`、ピアノは `0x1a1714`）なので、そこに強さ 1.1 の金色の自己発光を足すと、**素の色が完全に金色に塗りつぶされます**。白鍵も 0.55 で黄土色に寄ります。

### 求めること

**「押したことが一目で分かる」ことは残したまま、鍵が鍵に見えるようにしてください。**

- **黒鍵は押しても黒いまま**、白鍵は押しても白いまま（象牙色のまま）に見えること。色が変わったのではなく「押されている」と分かること。
- 見せ方はあなたが選んでください。案（縛られなくてよい）：
  - 自己発光をやめ、**沈みと影**で見せる（今すでに鍵は 1 cm 沈みます。鍵の間の影が濃くなれば十分伝わるかもしれません）。
  - 光らせるなら**鍵の手前の小口（縁）だけ**を細く光らせる。上面は素の色のまま。
  - 光の強さを大幅に下げる（例：黒鍵 0.1 前後）、色を金ではなく**その鍵自身の色を明るくした色**にする。
  - 鍵の下・すき間から漏れる光にする。
- **ピアノとバンドの両方**を直してください。2 つは別のファイルに同じ書き方があります。
- ピアノロールの「点灯は金色」という決まり（さとるんの指定）は**画面の左側（ピアノロール）の話**です。3D の鍵盤まで金色にする必要はありません。
- 判定できる検査を足してください（例：押した鍵と押していない鍵の、画面上の色の差。押した鍵の色が素の色からどれだけ離れたか。黒鍵が白鍵より明るくなっていないこと）。

## 直してほしいこと 2（さとるんの指摘）：**ハイハットを叩く左手の向きが不自然**

さとるんの言葉：
> 「シンセドラムのハイハット叩いてる手の向きが変な気がするのですが、これを自然にしたら、治すの超大変でしょうか？」

添付 `p2-band-hh-real.png`（硝子の環流 64.5 拍・ハイハット）と `p2-band-stick.png`（60 拍）を見てください。Claude の見立て：

- **手のひらが上を向いています。** 指が上に向かって丸まり、手の甲が下を向いています。ドラムを叩く手は、ふつう甲が上（または内側）で、手のひらは下か内側です。今はスティックを下から支えるような形です。
- スティックの軸まわりの**回転（ロール）が 180 度ずれている**ように見えます。
- 前腕が太い白い筒で、精密になった手と釣り合っていません。手首の黒い玉も大きすぎます。

思い当たる所（`public/band/scene.js` 731〜740 行あたり）：

```js
const dir = ss.tip.clone().sub(Sh.clone().add(V(-.06,-.10,-.18))).normalize();
const localUp = V(0,1,0).addScaledVector(STICK_AXIS,-STICK_AXIS.y).normalize();
const worldUp = V(0,1,0).addScaledVector(dir,-dir.y).normalize();
```

スティックの向きを「肩 → スティックの先」で決め、上方向を「世界の上」から作っています。この `localUp` が手のどちら側（甲か手のひらか）に当たるかを決めていないので、ロールが裏返っていると思われます。

### 求めること

- ハイハット・スネア・タム・クラッシュのどれを叩くときも、**甲が上（または外側）・手のひらが下（または内側）** の、ドラマーとして自然な握りにする。
- スティックの先が打面の正しい位置に当たることは**今までどおり保つ**（`bandRehearse` の打点の合格を崩さない）。スティックの向きは「肩 → 先」に縛られなくてよく、腕の自然な角度から決めて、手首の位置を逆算する形でも構いません。
- 前腕の太さ・手首の玉の大きさを、精密になった手と釣り合う形に。
- 叩く瞬間の手首の返し（スナップ）があると、なお良いです。
- 判定できる検査を足してください（例：叩く瞬間の手の甲の向きが上半球を向いているか。スティックの軸と前腕のなす角が人として無理のない範囲か）。全曲・全打点で。

**さとるんへの答えとして、これが「超大変」かどうかも書いてください。** Claude の見立ては「向きを決める十数行の話なので、直し自体は大きくない。ただし見た目が自然に見えるまでに調整が要る」です。あなたの判断を書いてください。
