## 直してほしいこと 1：手の動きが曲についていけない（最優先）

さとるんの言葉：「**革命の前に追加した曲の指の動きが、ちゃんとついていけてない**」。

「革命の前に追加した曲」＝同梱曲のうち古い 4 曲です（`public/piano/repertoire/index.json` の上から 4 つ）。

| 曲 | ファイル | 演奏解釈 | 音数 | テンポ |
|---|---|---|---|---|
| The Entertainer | `entertainer.mid` → `entertainer.vesper.json` | あり（Fable 5.1） | 2621 | 88 |
| Für Elise | `fur_Elise_WoO59.mid` | **なし**（`autoFinger`） | 905 | 72 |
| Clair de Lune | `debussy_Ste_Bergamesq_Clair.mid` | **なし**（`autoFinger`） | 1468 | 60 |
| Trois Nouvelles Études No.1 | `TroisNouvellesEtudes_Chopin_n1.mid` | **なし**（`autoFinger`） | 829 | 100 |

後から足した曲（革命・祭囃子・トルコ行進曲・幻想即興曲・子犬のワルツ・ジムノペディ・悲愴）は全部 Fable 5.1 の演奏解釈つきで、手と指（`h` / `f`）とペダルが曲データに入っています。古い 3 曲だけ、それが無くて `autoFinger` のルールで毎回決めています。

### Claude が測った事実（あなたはブラウザを使えないので、ここが唯一の観測です）

**(a) 指の付け替えが多すぎる。** 同じ手で同じ鍵を弾くのに、前と違う指番号が割り当てられる回数：

| 曲 | 指が変わった回数 / 全音数 | 割合 |
|---|---|---|
| Für Elise | 356 / 905 | 39% |
| Clair de Lune | 628 / 1468 | 43% |
| Trois Nouvelles Études | 495 / 829 | 60% |

`autoFinger` が音のかたまりごとに独立に指を決めていて、前後のつながりを見ていないためです。さらに `scene.js` の `update()` の中に「同じ指に 2 音が来たら、その瞬間だけ振り直す」仕組みがあり、フレームごとに指が入れ替わって、手が落ち着きません。

**(b) ペダルが無い。** Für Elise と Clair de Lune は MIDI に CC64 が入っておらず、`song.pedal` が 0 区間です（Trois Nouvelles は 54 区間あり）。`noteEndBeat`（`state.js`）はペダル中の音を伸ばすので、ペダルが無いと音が切れ、手も「押さえたまま」にならず、動きが忙しくなります。

**(c) 強弱が一定。** Für Elise は全音が強さ 62、Clair de Lune は全音が 90。表情がありません。

**(d) 跳びの数**（同じ手で 1 オクターブ以上動く回数。かっこ内は 0.2 秒未満で跳ぶ回数）：

| 曲 | 左手 | 右手 | 片手の最速 |
|---|---|---|---|
| Für Elise | 61 (0) | 19 (**4**) | 右 115 半音/秒 |
| Clair de Lune | 73 (0) | 32 (0) | 右 72 半音/秒 |
| Trois Nouvelles | 8 (0) | 10 (0) | 右 73 半音/秒 |

**(e) 今の動きの仕組みの弱点**（`scene.js` の `update()`）：
- 手の横位置は `st.x = lerp(st.x, palmX, Math.min(1, dt * 55))`。これは**フレームの速さに結果が左右される**書き方で、フレームが落ちると追いつきません。時間で決まる形（例：`1 - Math.exp(-k * dt)`）に直すか、速度の上限を持つ動きにしてください。
- 先読みは `LEAD = 0.10` 秒だけ。1 オクターブの跳びには短すぎます。跳ぶ距離に応じて先読みを伸ばす（遠いほど早く動き出す）べきです。
- `rehearse()` は「音の始まり」と「60ms 後」の 2 点しか見ません。**その間に手が間に合っているか**、**跳んでいる途中の速さが人間離れしていないか**は見ていません。だから「rehearse はずれ 0 なのに、見ると追いつけていない」が起きます。

※ Claude は、この作業用ブラウザが裏に隠れると描画が止まるため、実際の毎秒コマ数での追従は測れませんでした（測ると 0.4 コマ/秒になってしまう）。**「60 コマ/秒だから大丈夫」と仮定しないでください。** さとるんの画面では確かに追いつけていません。

### 求めること

1. **`autoFinger`（`public/js/fingering.js`）を作り直す。** 曲全体を見て、手の移動が少なく、指の付け替えが少ない運指を決める（例：手の位置を状態として持ち、前の指使いからの自然さを点数にして、区間ごとに一番良い並びを選ぶ）。目安：**同じ鍵で指が変わる回数を、上の表の 1/4 以下**に。ピアノの運指の常識（親指くぐり、黒鍵は 1・5 指を避ける、同音連打は指を替える、和音は開きに合わせる）を入れてください。
2. **`scene.js` の手の動きを、フレームが落ちても追いつく形にする。** 時間で決まる補間、跳びの距離に応じた先読み、腕の速度の上限（人間の限界に近い値。守れない曲が出たら、どこでどれだけ無理かを検査で出す）。フレームが 30・20・12 コマ/秒でも、音の始まりに指が鍵の上にある状態を保つ。
3. **`scene.js` の「その瞬間だけ指を振り直す」仕組みを落ち着かせる。** いったん決めた指はできるだけ保つ（ヒステリシス）。振り直すなら、その音が終わるまで保つ。
4. **新しい検査道具 `tools/piano-motion-check.mjs`**（Node で動く。ブラウザ不要）を作る：
   - 同梱曲を全部読み、`rehearse` と同じ判定に加えて、**コマ落ちに強いか**（60 / 30 / 20 / 12 コマ/秒で回す）、**手の移動速度の最大**、**指の付け替え回数**、**先読みが間に合っているか**を出す。
   - 合格の線をあなたが決めて、全曲合格にする。`scene.js` が three.js（`public/vendor/three/three.module.js`、import 名 `three`）に依存するので、Node で読めるようにする工夫が要ります（バンドで作った `tools/band-node-loader.mjs` と同じ手が使えます。使うときは実行の旗も文書に書いてください）。
5. **ペダルと強弱の無い 3 曲をどうするか。** 音楽の解釈（強弱・ペダル）は Claude 側が Fable 5.1 で後から付けます（あなたはやらなくてよい）。ただし、**ペダルが 0 区間の曲でも手が破綻しない**ようにしてください（押さえたままにできない音は手放す、など今ある仕組みの調整）。

## 直してほしいこと 2：カメラワークをバンドと同じ質に

さとるんの言葉：「**vesper band と比べてカメラワークが微妙なので、同じようにカメラワークをつけて欲しい**」。

### 今の差

**バンド（`public/band/scene.js`）**
- 寄りカメラに `closeMode = "auto"` があり、**今いちばん見どころの所へ自動で切り替わる**（つまみを回していれば「つまみ」、タムやクラッシュが来れば「ドラム」、ふだんは「鍵盤」）。切り替えには 0.35 秒の待ちがあり、ばたつかない（`_closeSwitchT`）。
- 切り替え先の位置は、右手の位置に合わせて動く（`kb.localToWorld(...)` で手の x に追従）。
- カメラの位置も狙いも `lerp(..., dt * 2.5)` でなめらかに動く（`_cp` / `_cl`）。
- 目線カメラの狙いも、次の打点を先読みして向く（`hitNext._sec - now < 0.25`）。
- 広角は `o.theta = 0.45 + 0.7 * sin(t * 0.05)` でゆっくり行き来する。
- 画面の下に「寄りカメラの狙い」を選ぶボタン（`.cbtn[data-close]`：auto / keys / drums / knobs）がある。

**ピアノ（`public/piano/scene.js`）**
- 寄りカメラ `camHands` は**固定の決め打ち**：`this.camHands.lookAt(hx * 0.85, KEY_TOP_Y - 0.02, -0.07)` で、両手の中間あたりをただ見るだけ。切り替えも先読みも無い。
- 広角は `o.theta = 0.85 + 0.55 * sin(t * 0.05)` で回るだけ。
- 目線カメラは `_eyeLook` を lerp するが、次に弾く場所の先読みが弱い。

### 求めること

ピアノの見どころに合わせた自動カメラを作ってください。ピアノの見どころは、バンドとは違います（案です。あなたの判断で良くしてください）：
- **主旋律を弾いている手**に寄る（音の数・強さ・高さから、今どちらの手が主役かを決める）。
- **跳ぶ直前**は、跳び先が見えるように引く／先回りする。
- **両手が遠く離れたとき**は 2 つとも入る画角に引く。
- **和音を押さえた瞬間**や**ペダルを踏み替える所**は、それが分かる角度に。
- 山場（強さが大きい所）では少し寄る・少し低い角度から、など「演奏を見せる」意識で。
- 切り替えはばたつかないこと（バンドと同じく待ち時間とヒステリシス）。カメラの動きはなめらかに。
- **手で操作したら自動をやめる**（今の `o.auto = false` と同じ考え方）。画面のボタンで「自動 / 左手 / 右手 / 両手」などを選べるようにし、既定は自動。
- バンドと同じく、**止まった絵を撮る入口**を作ってください：`window.pianoShot({ view, beat })` と `?song=...&shot=...&beat=...`。Claude が写真を撮って、あなたに見せられるようにするためです（バンドの `captureShot` / `astra/shot.mjs` と同じ流れ）。`window.pianoShotStatus = { state: "ready" | ... }` を用意してください。

## 直してほしいこと 3：音が小さい

さとるんの言葉：「**band と比べてだいぶ音が小さいので、その辺も調整をお願いします**」。

### Claude が実際に鳴らして測った値（マスターの出力。音量つまみは両方とも既定の -4 dB）

| | ピアノ（The Entertainer） | バンド（硝子の環流） | 差 |
|---|---|---|---|
| いちばん大きい所 | -21.6 dB | -14.7 dB | **6.9 dB** |
| 上位 10% | -27.4 dB | -17.4 dB | **10.0 dB** |
| 中央 | -30.5 dB | -20.1 dB | **10.4 dB** |

トラックの音量：ピアノは 1 本で -4 dB。バンドは 3 本（シンセ -1 / 足鍵盤 -2 / ドラム -5）。
さらに、演奏解釈で強さを抑えた曲があります（ジムノペディは強さ 25〜56、悲愴は 24〜90）。これは音楽として正しいので、**その曲だけ極端に小さくならない**ようにしたい、という話です。

### 求めること

- ピアノの出力をバンドと**そろえる**（中央で 8〜10 dB 上げるのが目安。ただし数字合わせではなく、耳で自然に）。
- **ピアノらしい強弱の幅は残す**。全部を潰して大きくするのは NG。`public/js/mix.js` のマスター（幅 → バスコンプ → 音量 → リミッター）と `public/js/sampler.js` の音量計算（`velGain`：`amp_veltrack` の 2 乗カーブ、`vt=0.73`）のどこで直すのが正しいか、あなたが判断してください。
  - 参考（HANDOFF1 10 章）：音源は強さで 8 段階の録音を切り替え、その上に 2 乗カーブを掛けるので、弱い音が実際より小さくなりすぎる傾向があります。
- **曲ごとの差を均す仕組み**を入れてよい（例：曲を読み込んだときに、その曲の音符から目標の音量を計算してトラック音量を決める）。ただし再生中に動くもの（強い自動音量調整）は、ピアノの表情を壊すので避けてください。
- 同梱 11 曲すべてについて、**あなたが計算した予想の大きさの表**を最後の返事に出してください（Claude が実際に鳴らして確かめます）。
- WAV 書き出し（`renderSong`、目標 -14 LUFS）との整合も見てください。

## Claude が確かめる入口

Claude はブラウザで `http://localhost:5173/piano/` を開き、次で確かめます。これが動くように保ってください（今あるもの）：
- `window.vesperStage`（3D）、`window.vesperRoll`（ピアノロール）、`window.vesperInterpret`（演奏解釈）。
- `vesperStage.rehearse(notes, pedal, beatToSec)` → `{ notes, checked, misses, maxDx, maxDy, maxDz }`。
- 曲を選ぶ：`document.querySelector('#btn-songs').click()` → `.lib-row button.lib-open` を押す。

これに加えて、今回作ってほしい入口：
- `?song=<index.json の file か perf のファイル名>` でその曲を開いた状態で立ち上がる。
- `window.pianoShot({ view, beat })` / `?shot=...&beat=...` と `window.pianoShotStatus`。
- コマ落ちを真似て確かめる入口（例：`vesperStage.setFrameRate(20)` のような、検査用にコマ数を落とす仕組み）。
