これは1回目の変更記録。写真を受けた2回目の仕上げと現在の判定は [PIANO_FINISH_2.md](PIANO_FINISH_2.md) を参照。

手・カメラ・音量の実装と Node 検査を追加した。**11曲中10曲合格。祭囃子の144拍目の1音は未達**。ブラウザでの見た目と実音は未確認。公開操作は行っていない。

## 手と指

- `public/js/fingering.js`：和音だけで独立に決める方法から、曲全体の手の位置と、以前その鍵を弾いた指を覚える方法へ変更。和音の指順、黒鍵の端の指、親指くぐり、速い同音連打を扱う。既に書かれている手・指を保ち、入力を変更せずコピーを返す。
- `public/piano/motion.js`：読み込み後に接触する指と手の移動経路を作る。移動する距離と使える時間から先読みを決める。最大先読み0.48秒、手首の速度上限3.0 m/s。これはアニメーションの設計上限で、人体の限界を実測した値ではない。
- 手の位置は曲の秒数から直接求める。コマ数によって前の位置から遅れて追いかける処理を廃した。指の割り当ては、その音の途中では変えない。移動中も指が届く間は押さえ、届かなくなる時や次の音で同じ指が必要な時に手放す。ペダルのない曲にも同じ処理を使う。音符の長さと音声側のペダル処理は変更しない。
- `public/piano/scene.js`：指の2節と指腹のずれを含めて関節角を直接解く。実際の指・腕の骨を使い、接触点の付け替えや手の瞬間移動で検査を通さない。手の届く位置の範囲を使い、細かな音ごとに手首を中央へ戻さない。移動の上下動は始めと終わりの速度を0にする。
- 鍵とペダルの状態も曲の時刻から求める。体は音の直後のゆるやかな動きと呼吸を重ねる。

`rehearse(notes,pedal,beatToSec)` は既存の戻り値を保持する。発音を次の描画時刻に切り上げず、全音の開始時刻を検査する。保持している音については60ms後も調べる。発音時の音を「手放した」として検査から除外しない。

## 合格条件と結果

`tools/piano-motion-check.mjs` は描画しない実際の THREE の骨・関節を使う。キャンバスへの文字・木目の描画だけを代用品にしている。

- 指先は鍵の幅内、許可された奥行き内、鍵の上面から8mm以内。従来の接触許容値を拡大していない。
- 全音の開始1ms前の準備位置を別に確認する。準備中の指には25mmまでの高さを許し、発音時には8mmの基準を使う。
- 60 / 30 / 20 / 12 FPS の各描画時刻で、実際に押している指の接触と実際の手首の速度を測る。240 Hzでも移動経路を検査する。音の途中の指の変更は0回が条件。
- 未解釈の3曲は、読み込み時・表示時とも、同じ手・同じ鍵で前回と指が変わる回数が旧版の1/4以下であること。
- 同梱データが速度上限を守れない場合は拍、距離、必要速度、不足時間を出し、終了コード1にする。

数値の正本は `astra/piano-motion-final.json`。音が描画の間に始まって終わる数も `betweenFrames` として出す。12 FPSでは83msより短い音をすべて画面に出すことはできない。その音も発音時刻の検査からは除外しない。

### 祭囃子で残る1音

右手が143.9333拍のMIDI 93から、144拍のMIDI 59へ移る。発音間隔は約26ms、計画上使える移動時間は約22ms。手の形を広げても今回の経路では約18.5cmの移動が必要で、必要な最高速度は約9.16 m/s。3.0 m/sに制限すると約45ms不足する。

144拍には左手のMIDI 35も同時にある。左手だけで35と59を押さえるには2オクターブの開きが必要なため、この1音を左手へ渡す方法でも今回の手の形では解決しない。

コードは速度を制限し、144拍目のMIDI 59への接触を失敗として返す。60 FPSでは実際の描画でも1回ずれる。30 / 20 / 12 FPSではその瞬間が描画の間に入るため0回になるが、発音時刻の検査は全条件で不合格を保持する。データを変えず全曲合格、という条件は達成していない。

## カメラと撮影

`scene.js` は音の密度・強さ・高さを使い、主役の手を選ぶ。広い両手、跳び先、和音、静かな部分のペダル交換を画角に反映する。主役の切り替えには0.35秒の待ちと0.9秒の保持を設けた。跳びの画角は最大0.55秒前から広げ、主役の切り替えを待たない。位置と狙いには時間に基づくなめらかな補間を使う。

`index.html` / `style.css` に「自動 / 左手 / 右手 / 両手」を追加。寄り画面をドラッグ・ホイール操作すると、そのカメラの自動を止める。「自動」またはダブルクリックで戻す。全体カメラの手動操作も従来どおり自動回転を止める。

入口は `piano.js` にある。

```js
await window.pianoReady;
await window.pianoLoad('fur_Elise_WoO59.mid');
vesperStage.setFrameRate(20); // 0で通常の描画に戻る
await window.pianoShot({view:'right',beat:46.75});
window.pianoShotStatus; // {state:'ready',view,beat,ms}
window.pianoShotEnd();
```

撮影は音を出さず、準備が終わった画像を1回描いて保持する。`pianoShotReady` は完了を待つPromise。失敗時は `state:'error'`。曲・拍・カメラが同じなら手の姿勢を再現する。

通常の再生も、手の経路を準備してから音を開始する。最初の準備時間を発音後の遅れにしない。

対応するview：`full`, `wide`, `side`, `top`, `eye`, `left`, `right`, `both`, `keys`（自動の寄り）, `pedal`。

URL例：`http://localhost:5173/piano/?song=fur_Elise_WoO59.mid&shot=right&beat=46.75`。`song` は曲目の `file` と `perf` のどちらも使える。拍は0始まり。既存の `vesperStage`, `vesperRoll`, `vesperInterpret`、曲一覧のボタンも保持している。

`astra/shot.mjs` は piano / band いずれのreadyも待ち、未準備・errorを成功画像として保存しない。撮影ツール自体は今回実行していない。

## 音量

- `public/piano/sample-energy.json`：既存のSalamander 240録音から測った、50msごとの音の強さ。先頭2秒を使い、その後は減衰を近似する。素材の追加や音源の加工ではない。
- `public/piano/loudness.js`：録音の段階、音の高さ・長さ・重なり・ペダルから、曲ごとに一定の補正量を決める。音量つまみの値を打ち消さない。静かな曲は少し静かなまま残す。
- `sampler.js` / `audio.js`：ピアノ画面が指定した出力だけ、追加のベロシティ追従を0.73から0.35へ弱める。録音の8段階と音符の強弱は残る。共有の音源インスタンス全体の設定は変えない。
- `mix.js`：ピアノの補正をバスコンプの後、リミッターの前へ加える。音量を上げるためにコンプへ強く押し込む処理は使わない。補正指定のないBAND / STUDIOは従来の設定を使う。

補正は曲を開いた時や停止中の曲変更で決め、再生中の音量には追従しない。`window.pianoLoudness` で計算結果を確認できる。
